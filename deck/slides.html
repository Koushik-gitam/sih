Problem Context

Why DoCA Needs This: The Manual Reporting Bottleneck

Every commercial scale and weighbridge in India needs Model Approval. Laboratories produce the evidence that decides it — and that evidence is still built by hand.

✗ Today — manual status quo

  • ✗Observations recorded on paper and unstructured spreadsheets at each load point.
  • ✗MPE brackets and change-over true error (Ec) computed by hand — dozens of repetitive calculations per test.
  • ✗No standard report layout: every laboratory formats results differently.
  • ✗No central repository, no audit trail, no way to verify a past approval.

✓ With this platform — automated

  • ✓Structured digital entry per OIML R 76 test module, with pre-entry validation.
  • ✓Errors, MPE brackets and verdicts computed instantly by a deterministic engine.
  • ✓One report format (OIML R 76-2) rendered identically as PDF and editable .docx.
  • ✓Searchable repository with immutable audit ledger and SHA-256 report hashing.
⚠ Domain risk: MPE is not a fixed number. It shifts with accuracy class, verification scale interval e and applied load, so a single spreadsheet formula propagated across load points silently produces wrong verdicts — and rejected or delayed Model Approval applications.

Metrological Core: Dynamic MPE & True Error

The rule set is data, not code: class-wise MPE brackets and error formulas live in an editable JSON schema.

MPE for initial verification — load m in intervals e (OIML R 76-1 Table 6)

Class±0.5 e for±1.0 e for±1.5 e for
I0 ≤ m ≤ 50 00050 000 < m ≤ 200 000m > 200 000
II0 ≤ m ≤ 5 0005 000 < m ≤ 20 00020 000 < m ≤ 100 000
III0 ≤ m ≤ 500500 < m ≤ 2 0002 000 < m ≤ 10 000
IIII0 ≤ m ≤ 5050 < m ≤ 200200 < m ≤ 1 000

m = L / e  where L is the applied load and e the verification scale interval. Bracket selection is automatic from the instrument record.

Validation built in: Max ≥ Min, Min ≥ 20e (class III), e and d consistency, load ≤ Max, duplicate/missing load points.

E = I + 0.5e − ΔL − L Error before correction — I = indication, ΔL = additional sub-weights to reach change-over, L = applied load
Ec = E − E0 True error at the change-over point, corrected for the error at zero load
Observation grid → L, I, ΔL
▼
m = L/e → MPE bracket for accuracy class
▼
|Ec| ≤ MPE ? PASS FAIL

Modules covered: weighing (increasing / decreasing), eccentricity, repeatability (σ), tare & zero-setting, temperature and voltage influence.

Trust & Resilience

Integrity, Offline Operation and Future-Proofing

A metrology report is evidence. The system is designed so that evidence cannot be quietly altered.

🔒 Tamper-evident records

  • SHA-256 integrity hash printed on every generated report.
  • Append-only audit ledger: who entered, edited, approved and when.
  • State locking — a submitted module is read-only unless a manager unlocks it with a recorded reason.

☁ Offline resilience

  • All calculations run locally; no network needed during a test.
  • Draft tests persist in IndexedDB and survive page reloads at site.
  • Service worker caches the application shell for zero-connectivity field use, then syncs.

⇄ Rules as data

  • MPE brackets, class limits, tolerances and test modules are declared in a versioned JSON schema.
  • When OIML R 76 or LM Rules are revised, an administrator updates the schema — no engine rewrite.
  • Rule version is stamped into each report for traceability.

☺ Access control

  • Technician, Lab Manager, Administrator and Auditor roles.
  • Server-side enforcement of every role permission, not just hidden UI.
  • Hashed credentials and signed session tokens.
